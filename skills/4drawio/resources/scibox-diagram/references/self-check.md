# 自检纪律

## 为什么需要

写 XML 的人看不见自己画出来的东西。坐标、样式串在文本里全都"合理"，但箭头被标签盖住、下标被线横穿、盒子被文字撑破——这些只在渲染图里现形。所以自检不是"再读一遍 XML"，而是**把判断权交给两样外部证据**：静态检查的退出码，和裁到画布的截图。

配套的两条铁律：**没跑 `check_layout.py` 不许出预览；没看渲染图不算画完。**

## 九区盘点

每轮截图后按区扫，不要只盯最显眼的一处。逐区问自己：

| 区 | 看什么 |
|---|---|
| 文字 | 溢出盒外？被线横穿？下标下探压线？该断行的地方自动折行了？ |
| 箭头 | 方向对不对？该扇出的画成了并列直线？双向画成了单向？箭头压住文字？ |
| 盒子 | 有重叠或被挤扁的吗？同族尺寸一致吗？圆角风格统一吗？ |
| 间距 | 同族步距是否一致？族间留白是否明显大于族内？ |
| 配色 | 颜色种类是否收敛（5–8 种）？同语义是否同色？有没有无含义的装饰色块？ |
| 字体层级 | 字号种类几种？层级是否与信息重要性一致？有没有"因为是标题就放大"？ |
| 版面 | 整体重心偏移？大片空白？某一带过挤？ |
| 图标 | 同类图标是否同一配方、同一描边和尺寸？ |
| 风格一致性 | 整张图看起来像一个人画的，还是像几张图拼的？ |

**发现的问题要一次改完再重渲**，不要挑最容易的改。每条记录状态：已修 / 未修 / 部分修 / 引入回退。

## 红队复审

修完之后**换身份再看一遍**：你不再是作者，你是想挑毛病的评审。作者视角会自动忽略自己刚"处理过"的地方，这一步就是为了抵消它。

重点盯这些容易自欺的地方：

- 箭头的**语义**而不只是外观：谁到谁、单向还是双向、扇入扇出画对了吗；
- 连接器有没有穿过文字、穿过盒子、走出不可能的路径；
- 分组括号、双向箭头的朝向；
- 最近一次修改**引入的新问题**（改 A 撞坏 B 是常态）；
- 数值、术语有没有抄错——这条比任何排版问题都严重。

我这套流程里真正被红队抓到过的两类错误，可以作为参照：一是**箭头方向整体画反**（把"视角驱动推演"画成了"推演产出视角"），二是**文案歧义**（"12 月 21 日"实际想说的是"各月 21 日"）。两者在缩略图上都看不出来，都是放大和重读才发现的。

## 自评分卡

交付前给自己打分，每扣一分都要能指出**截图上的具体位置**：

| 维度 | 分 |
|---|---|
| 文字可读性 | /10 |
| 箭头准确性 | /10 |
| 配色一致性 | /10 |
| 版面一致性 | /10 |
| 风格贴合度（对参考图或既定风格） | /10 |
| **合计** | **/50** |

- **< 40 或任一维 ≤ 4**：不许交付，继续改。
- **40–44**：可交付，但要在交付说明里列出接下来会改的几处。
- **≥ 45**：可交付。

打不出扣分依据说明没认真看图——回去重扫九区。反过来，图确实干净时不要为了凑数编缺陷。

## 交付前清单

- [ ] `.drawio` 能解析，画布尺寸是有意为之；
- [ ] `check_layout.py` 无 FAIL；
- [ ] 最新一版**渲染图**已逐区看过（不是只看 XML）；
- [ ] 图里没有 `data:image/png|jpeg` 位图（要求可编辑时，位图整块不可改）；
- [ ] 数值、术语与源材料核对过；
- [ ] 遗留差异与有意近似逐条写清，不说"已完美还原"；
- [ ] 走模板路径时，content JSON 一并留存，便于复现和二次修改。
