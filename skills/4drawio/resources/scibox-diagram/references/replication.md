# 高保真复刻参考图

用户给一张图片，要求重画成可编辑矢量图时走这套流程。核心思路：**先把图片变成一份机械的测量结果，再照测量结果画，最后用渲染图逐轮比对**。凭肉眼估坐标和配色，出来一定是"神似形不似"。

## 硬规则

1. 中间产物没写完，不许动 XML。
2. 主产物是 `.drawio`；PNG 只是核对手段，不能当交付物。
3. **不许悄悄省略元素**。画不出来的（复杂图标、位图纹理）写进 `asset-ledger.md`，不要装作没看见。
4. 不只复刻几何，还要复刻**语义**：每根箭头的起止、方向、是扇入还是扇出，画之前要能说出来。
5. 不用"差不多"结案。残留差异逐条写进 `defect-log.md`。
6. 首张截图之后，`defect-log.md` **只增不改**——旧结论错了就追加一条更正，不要抹掉历史。

## 一、标定：把图片变成数字

别目测。下面几步是实测有效的做法（`roadmap-5band` 模板就是这么标出来的），需要 `numpy / scipy / Pillow`。

**盒子坐标与填充色**——把"非描边"区域连通域化，逐个填洞后取矩形外接框：

```python
lum = a.mean(axis=2); sat = a.max(axis=2) - a.min(axis=2)
stroke = (lum < 205) | ((sat > 45) & (lum < 235))      # 描边或深色文字
lab, n = ndimage.label(~stroke)
for i, sl in enumerate(ndimage.find_objects(lab), 1):
    m = ndimage.binary_fill_holes(lab[sl] == i)        # 填掉文字造成的孔洞
    if m.sum() / m.size > 0.88:                        # 只留矩形区域
        ys, xs = sl                                    # -> x/y/w/h
        fill = np.median(a[sl][lab[sl] == i], axis=0)  # -> 填充色
```

注意：**中等饱和度的填充色会被 `stroke` 规则误吞**（如 `#b8d8f8`），这类盒子要用"按目标色 ± 容差取掩膜 + 填洞"单独再扫一遍。

**外框、分带线、虚线框**——整行/整列扫描"笔画覆盖率"：实线接近 100%，虚线落在 40–70%。把区间切成 20+ 段、要求每段都有笔画，可以排除"由多个盒子拼出来的假横线"。

**配色**——对整图做颜色普查（量化到 8 级后计数），取占比最高的若干种；再在具体元素上取中位色确认。不要从截图里"看着像"取色。

**字号**——量一行已知字数的像素宽度 ÷ 字数 = 单字宽 ≈ 字号。**不要假设标题一定比正文大**：学术模板常常是扁平字号（标题和正文都是 16px），照着"标题应该更大"画就会失真。

**画布**——直接用参考图的像素尺寸做画布，1 单位 = 1 像素，后面所有坐标可以原样搬。

## 二、四件中间产物

写在 `.drawio` 旁边，名字固定，便于回查。

**`visual-spec.md`**——看到了什么：
`## 来源`（参考图路径、画布、字体策略）、`## 全局样式`（背景、字体、描边、箭头、**配色表：角色 / hex / 采样位置**）、`## 区域`（id + bbox + 作用）、`## 文本块`（id + bbox + 原文 + 字号 + 对齐）、`## 形状`（id + bbox + 填充 + 文本）、`## 连接器`（id + 起止 + 路由 + 箭头 + 标签）、`## 语义关系`（每条连接的**含义**与基数）、`## 图标`（bbox + 含义 + 精确/近似/缺失 + 方案）。

**`layout-grid.md`**——坐标计划：画布与页边距、栅格线表（名称 / x / y / 用途）、区域盒表、**重复族**（族名 / 数量 / 单元尺寸 / 步距 / 起点）、绘制顺序（背景 → 容器 → 内部图元 → 连接器 → 文字 → 图标 → 高亮）。

**`asset-ledger.md`**——防止悄悄丢东西：精确素材、原语近似（用什么拼的、保真度差在哪）、无法获得的素材（缺什么、需要用户提供什么）。水印之类**有意不复刻**的也写在这里。

**`defect-log.md`**——工程账本：`Pass 0` 计划期风险；`Pass N` 每轮截图的缺陷表（缺陷 / 截图证据 / 参考图证据 / 要改哪些 cell / 修法 / 状态）；截图证据表（第几轮 / 路径 / **截图类型** / 是否全画布）；需求与语义审计；红队复审；遗留差异。

## 三、迭代闭环

**至少 3 轮**，每轮 = 截图 → 全区盘点 → 修完**所有** P0/P1 → 重渲 → 逐条核销（FIXED / 未修 / 部分 / 回退）。

截图纪律：**必须是画布本身**。带浏览器工具栏、侧栏的截图里图太小，看不出压线和溢出，这种截图不能用来判定质量。用 `scripts/export_figure.py` 直接导 1:1 PNG 最省事；细节看不清就 `-s 2` 出双倍图，或用 Pillow 裁局部放大。

每轮盘点覆盖九个方面：文字、箭头、盒子、间距、配色、字体层级、版面、图标、整体风格一致性。别只盯着最显眼的一处改。

## 四、比对与验收

有参考图就别只靠眼睛，做**像素差分**定位差异：

```python
d = np.abs(ref.astype(int) - render.astype(int)).max(axis=2)
m = ndimage.binary_opening(ndimage.binary_closing(d > 70, np.ones((7,7))), np.ones((3,3)))
lab, _ = ndimage.label(m)          # 按面积排序，逐个去看最大的差异簇
```

注意参考图上的**水印、压缩噪点**会抬高整体差值，别被平均值误导——要看差异簇的位置和形状。

交付前确认：

- `.drawio` 能解析，画布尺寸与参考一致；
- `scripts/check_layout.py` 无 FAIL；
- 三轮以上迭代记录在案，最后一轮截图是全画布；
- 参考图里每个可见元素都有对应物，或在 `asset-ledger.md` 里有交代；
- 残留差异逐条列出，不写"已完美还原"。

## 五、结构性错误的处理

第一张截图如果**结构**就不对（整块错位、比例失衡），不要在 XML 上一点点挪。回到 `visual-spec.md` 和 `layout-grid.md`，找出是哪个观测或哪个坐标假设错了，先修计划再改图。常见根因：画布尺度搞错、把自动折行当成了手动断行、把两个相邻元素当成了一个、误判了某条线属于哪个图元。
