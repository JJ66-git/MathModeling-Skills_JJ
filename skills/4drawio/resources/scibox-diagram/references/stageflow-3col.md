# 模板 stageflow-3col · 分阶段流程框架图

三栏骨架：**左＝研究方法链**（白底竖排方框 + 深蓝粗箭头逐级推进）、**中＝彩色流程块**（每块一条实色标题条 + 独立色系的内部结构）、**右＝阶段说明**（左向块箭头，箭头体内竖排文字，指入对应的内容块）。画布宽固定 1000，高度按内容自动生长。

渲染：`python3 scripts/stageflow_3col.py content.json -o out.drawio`（写前逐槽校验中文字宽；`--check` 只校验）。

## 一、与 framework-3col 怎么选

两个都是三栏研究框架，区别在中栏的**视觉语言**和内部结构：

| | `framework-3col` | `stageflow-3col` |
|---|---|---|
| 中栏块 | 浅绿标题条，全图统一配色 | **实色标题条，每块一个色系** |
| 内部结构 | 归纳汇聚型（括号合流、对向机理） | **流程执行型**（阶段推进、决策分支、成果分发）|
| 左栏 | 渐变旗标（阶段名） | 白底竖排方框（方法名）+ 粗箭头 |
| 右栏 | 绿色方法清单 | 左向块箭头（阶段说明）|
| 适合 | 已完成研究的**内容全景** | 研究/系统的**执行流程** |

## 二、语义约定

- 中栏五块自上而下是**推进关系**（框架 → 阶段 → 数据 → 决策 → 成果），顺序有含义。
- **每块一个色系**（`tone`），块内所有元素共用该色系的深/浅两档。不要在一块里混用多个色系，也不要让两块用同一个 tone——颜色在这张图里承担"分块"的功能。
- 左栏方法、右栏说明都用 `block` 锚到对应内容块，保证三栏在同一水平线上互相对应。
- `groups` 段的双向箭头表示**阶段间可回溯迭代**；`scenarios` 段的菱形表示**判定**，左右竖排标签是判定的输入条件与约束——不要把普通条目画成菱形。

## 三、顶层字段

```jsonc
{
  "headers": ["研究框架", "研究内容", "研究方法"],
  "stages": [{"text": "文献研究法", "block": 0, "at": 0.42}],   // 左栏，2–8 个
  "rights": [{"text": "总体设计",  "block": 0, "at": 0.45}],   // 右栏，可省略
  "blocks": [{"title": "研究整体框架", "tone": "teal", "sections": [ … ]}]
}
```

`tone` 可选：`teal` / `green` / `olive` / `orange` / `blue`。
`block` + `at`：锚到第 `block` 个内容块（0 起）内的相对位置（0=顶，1=底）。

## 四、五种版式段

**`cards`** — N 张卡片，每张＝深色小标题 + 浅色描述块。适合"框架的 N 个组成面"。

```jsonc
{"type": "cards", "cards": [{"header": "理论基础", "desc": "文献综述、\n理论梳理与\n概念界定"}]}
```
卡片 3–6 张；`desc` 用 `\n` 断行，所有卡片的描述框按最多行数统一高度。

**`groups`** — N 个阶段组，每组＝标题 + 条目，组间自动加**双向粗箭头**（表示可迭代）。

```jsonc
{"type": "groups", "groups": [{"header": "需求调研", "items": ["文献梳理", "方案设计"]}]}
```
组数 2–4。

**`list_grid`** — 左列（标题 + 条目）→ 粗箭头 → 右侧（标题 + N 列网格）。适合"输入处理 → 多环节分析"。

```jsonc
{"type": "list_grid",
 "left":  {"header": "数据处理", "items": ["原始数据", "特征提取"]},
 "right": {"header": "模型训练与分析", "rows": [["模型初始化", "参数调优", "训练执行"]]}}
```
网格每行 2–4 列，行数不限。

**`scenarios`** — N 个场景并列，场景标题间用细双向箭头相连；每个场景下是「竖排输入 | 菱形判定 | 竖排约束」，再向下汇出一个结果盒。

```jsonc
{"type": "scenarios", "scenarios": [
  {"name": "场景 A", "left": "初始条件", "decide": "模型决策", "right": "外部约束", "out": "决策输出"}]}
```
场景 2–4 个；`left` / `right` 是竖排，建议 ≤5 字。

**`fanout`** — 一个中心盒经母线分发到 N 个结果盒。适合"核心成果 → 若干应用方向"。

```jsonc
{"type": "fanout", "center": "核心研究成果", "outs": ["理论贡献", "方法创新"]}
```
分支 3–6 个。

## 五、字数预算

字号：标题条 16、栏头 16、竖排 16、正文 14、卡片描述 12；行高＝字号+3。下表为默认数量下每行汉字上限，数量增加时槽位变窄——以脚本报错为准。

| 槽位 | 宽度 | 预算 |
|---|---|---|
| 栏头 `headers` | 120 | ≤6 汉字 |
| 左栏 `stages[].text` | 72 | 竖排，≤6 字（盒子按字数长高）|
| 右栏 `rights[].text` | 140（箭头体约 100）| 竖排，≤6 字 |
| 块标题 `title` | 403 | ≤24 汉字 |
| `cards` header / desc | 5 张时 118 | ≤7 汉字 / 描述 ≤9 汉字每行 |
| `groups` header / item | 3 组时 184 | ≤12 汉字 |
| `list_grid` 左列 | 143 | ≤9 汉字 |
| `list_grid` 网格单元 | 3 列时 148 | ≤9 汉字 |
| `scenarios` 场景名 | 3 个时 194 | ≤12 汉字 |
| `scenarios` 竖排标签 | 50 | ≤5 字 |
| `scenarios` 菱形 | 81 | ≤4 汉字（菱形有效区窄）|
| `fanout` center / outs | 468 / 5 个时 116 | ≤28 / ≤7 汉字 |
