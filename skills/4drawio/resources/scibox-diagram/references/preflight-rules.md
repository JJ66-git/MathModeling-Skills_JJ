# 静态检查：查什么、为什么、怎么绕

`scripts/check_layout.py` 在**看渲染图之前**先用几何算一遍。它存在的理由很简单：写 XML 的人看不见成品，而下面这些缺陷全都能从坐标和字符算出来，不必等截图。

```bash
python3 scripts/check_layout.py fig.drawio            # 体检
python3 scripts/check_layout.py fig.drawio --strict   # WARN 也算失败，可作交付门禁
```

## FAIL（必须清零）

| 规则 | 判据 | 为什么是硬错 |
|---|---|---|
| 文字溢出 | 某行宽 > 槽宽 − 8（单字行按 −2）；或行数 × (字号+3) > 槽高（无边框标签放宽到 1.4 倍） | 中文最常见的翻车点，渲染后文字会冲出边框或被压扁 |
| 越出画布 | 顶点超出 `pageWidth/Height` | 导出时被裁掉，PDF 里直接消失 |
| id 重复 | 同一 id 出现两次 | draw.io 行为未定义，且后续无法精确定位修改 |
| 盒子重叠 | 两个实体盒矩形相交 | 遮挡内容；容器与背景块已排除，不会误报 |
| 连线穿盒 | 线段与实体盒相交（自身端点所在盒除外） | 线从盒子中间穿过，语义与观感都错 |
| 内嵌位图 | style 含 `data:image/png\|jpeg` | 要求可编辑时，位图整块不可再改 |

## WARN（看情况）

| 规则 | 判据 | 处理 |
|---|---|---|
| 端点压边 | 连接器端点正好落在某盒边界上（±0.6px） | 外移 1px，见下 |
| 疑似空盒 | 有填充有描边、非形状、却没有文字 | 确认是不是漏填内容 |
| 字号种类过多 | 带文字的顶点字号 > 4 种 | 学术图 2–3 种足够，层级过多显乱 |
| 填充色发散 | 实体盒填充色 > 20 种 | 同语义应同色，否则像调色板打翻 |

## 刻意不查的

- **紧密堆叠的行列间距**。学术示意图里 3px 贴合的表格式堆叠是刻意排版，不是缺陷。通用检查器常把这类判成"元素几乎相触"，属噪声。
- **同族尺寸是否对齐**。机器判"同族"必然跨族误报——旗标和分带里的盒子只要 y 相同就会被配对。这一条交给人眼和 `authoring.md` 的排版纪律。
- **配色是否好看、版面是否舒服**。看渲染图。

低噪声是这个检查器的设计目标：在正常的图上应当是 `FAIL 0 WARN 0`，一旦报警就值得认真看。

## 四个规避手法

这些不是"骗过检查器"，而是**几何上确实更干净**的画法：

| 现象 | 原因 | 做法 |
|---|---|---|
| 端点被判压边 | 端点落在边界线上，既算"在盒内"又算"在盒外" | 所有连接器端点离盒边留 **1px** |
| 分组框里的元素被判重叠 | 无填充虚线框如果是实体顶点，会进入重叠矩阵 | 大虚线框保持 `fillColor=none;dashed=1`（检查器已豁免）；小虚线框改用**闭合折线**（四段 edge 首尾相接） |
| 背景色块与其上元素判重叠 | 有填充的顶点是实体盒 | 背景块设 `strokeColor=none`，会被当作文本层，不参与重叠判定 |
| 装饰性外框被判"穿盒" | 实线大矩形是碰撞目标，必然穿过内部元素 | 外框拆成折线段，并在被标题条、旗标遮挡处**留缺口**——既符合"线被压在下面"的视觉，也消除误判 |

## 与看图的关系

静态检查只覆盖能算的部分。**算不出来的仍然要靠眼睛**：箭头方向对不对、语义是否成立、同族是否对齐、整体重心是否偏、数值有没有抄错。所以顺序永远是：

```
check_layout.py（先过机器）→ export_figure.py（出 1:1 PNG）→ 逐区看图（见 self-check.md）
```
