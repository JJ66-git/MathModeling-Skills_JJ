# 模板 framework-3col · 三栏研究框架图

三栏骨架：**左＝研究阶段链**（渐变旗标，自上而下推进）、**中＝研究内容**（若干虚线大块，每块一个绿色标题条 + 若干版式段）、**右＝研究方法**（绿色方法清单，与内容块对应）。画布宽固定 1026，高度按内容自动生长。

渲染：`python3 scripts/framework_3col.py content.json -o out.drawio`（写文件前逐槽校验中文字宽，超框报出预算；`--check` 只校验）。

## 一、语义约定

- **三栏是"同一件事的三个视角"**：同一行高度上，左边的阶段、中间的内容、右边的方法应当互相对应。用 `block` / `at` 把旗标和方法块锚到对应的内容块上（见下），不要让它们各自等距漂移。
- **中栏块之间是推进关系**（提出 → 分析 → 解决 → 建议），不是并列清单；顺序不能随意调。
- **一个内容块可以对应多个阶段**（示例里块②对应"分析问题＋解决问题"，块③对应"影响机理＋重构路径"）——这正是要用锚点而不是等距的原因。
- 段内的括号合流、对向箭头都有含义：合流＝多因素汇成一个结论，对向＝两侧因素共同作用于中心。画不出这层意思就别用对应段型。

## 二、顶层字段

```jsonc
{
  "headers": ["研究框架", "研究内容", "研究方法"],   // 三个粉色栏头，各 ≤6 字
  "stages": [                                        // 左栏阶段，2–8 个
    {"text": "提出问题", "tone": "teal", "block": 0, "at": 0.28}
  ],
  "methods": [                                       // 右栏方法组，2–6 个
    {"text": "知识图谱\n专利计量", "block": 0, "at": 0.30}
  ],
  "blocks": [                                        // 中栏内容块，1–6 个
    {"title": "……", "sections": [ {"type": "…", …} ]}
  ]
}
```

- `tone`：`teal`（青绿）或 `sky`（浅蓝），用来区分阶段性质，不要每个都换色。
- `block` + `at`：锚到第 `block` 个内容块（0 起）内的相对位置（0=顶，1=底）。省略则该栏等距分布。
- `methods` 也可直接写字符串（等距分布）。

## 三、五种版式段

每个内容块的 `sections` 是一个数组，可叠多段（示例块③＝`mechanism` + `pair`）。

**`columns`** — N 列并列，每列"紫色小标题 + 若干黄色条目"，列间自动加橙色块箭头。适合"三个并列研究维度"。

```jsonc
{"type": "columns", "columns": [
  {"header": "维度 ①", "items": ["要素 A", "要素 B"]}
]}
```
列数 2–4；条目数不限（块会自动长高）；条目可用 `\n` 断成两行。

**`converge`** — 左右两组，每组"绿色小标题 + 若干条目 → 括号合流 → 若干竖排结论盒"。适合"多个因素归纳出结论"。

```jsonc
{"type": "converge", "groups": [
  {"header": "识别与解构",
   "items": ["关键环节 ①", "网络结构 ②"],
   "outs": ["结构特征归纳", "为下一步提供现实依据"]}
]}
```
组数 1–2；`outs` 是竖排窄盒（字号自动降到 11），高度按字数自适应。

**`mechanism`** — 左侧因素 → 括号 → 竖排标签 → 中心盒 ← 竖排标签 ← 括号 ← 右侧因素，中心盒下方接一个结论盒。这是最特化的一段，参数固定：

```jsonc
{"type": "mechanism",
 "left": ["因素 ①", "因素 ②"], "left_label": "影响因素",
 "center": "维度①+维度②\n+维度③",
 "right_label": "影响机理", "right": ["机理 ①"],
 "bottom": "____ 重构影响机理"}
```

**`pair`** — 左右两个子块：左＝"标题 + 竖排条目"，右＝"标题 + 两列网格"，中间一条紫色粗箭头。适合"要素 → 具体路径"。

```jsonc
{"type": "pair",
 "left":  {"header": "重构三要素", "items": ["要素重构 ①", "组织重构 ②"]},
 "right": {"header": "____ 重构模式与路径",
           "rows": [["全球产业链价值链联动", "产业链升级"]]}}
```

**`chain`** — 横向 N 个盒子用绿色箭头串联。适合"发展历程 → 评价 → 优化"这类线性流程。

```jsonc
{"type": "chain", "items": ["发展历程\n及成效", "评价体系构建", "优化建议"]}
```
项数 2–5。

内部结构完全不属于上述五类时，不要硬套：只保留块标题，内部按 `authoring.md` 手写补充。

## 四、字数预算

字号：块标题 16、栏头 16、其余 15、竖排结论盒 11；行高＝字号+3。下表为**默认数量**下的每行汉字上限，数量增加时槽位变窄、预算随之下降——以脚本报错为准。

| 槽位 | 宽度 | 预算 |
|---|---|---|
| 栏头 `headers` | 147 | ≤6 汉字 |
| 阶段旗标 `stages[].text` | 147（左对齐留 14） | ≤7 汉字 × ≤2 行 |
| 方法组 `methods[].text` | 146 | ≤8 汉字/行，行数不限（块随行数长高）|
| 块标题 `blocks[].title` | 501 | ≤30 汉字，单行 |
| `columns` header / item | 3 列时 176 | ≤10 汉字；item 可 2 行 |
| `converge` header | 2 组时 248 | ≤15 汉字 |
| `converge` item | 2 组时 161 | ≤9 汉字 |
| `converge` outs | 竖排 | 字数不限（盒子按字数长高），建议 ≤14 字 |
| `mechanism` left / right | 150 / 155 | ≤8 / ≤9 汉字 |
| `mechanism` center | 约 114 | ≤6 汉字 × ≤2 行 |
| `mechanism` bottom | 220 | ≤13 汉字 |
| `mechanism` 竖排标签 | 34 | ≤4 字 |
| `pair` 左 header / item | 235 / 203 | ≤14 / ≤12 汉字 |
| `pair` 右网格单元 | 2 列时 162 | ≤9 汉字 |
| `chain` item | 3 项时 166 | ≤9 汉字 × ≤2 行 |
