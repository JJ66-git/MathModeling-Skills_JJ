## 1. 规则优先级

按以下顺序解决格式冲突：

1. 当年赛事官方通知、论文规范和提交系统要求；
2. 项目实际使用的官方模板；
3. 用户提供的赛题专用说明；
4. 历年经验与本指南。

没有当年规则时，明确标记“格式待核对”。对 CUMCM 中文摘要，可把正文约 600-750 个汉字、3-5 个关键词、摘要单独一页作为排版启发，而不是跨年份硬性规则。MCM/ICM 的 Summary Sheet 必须服从当年 COMAP 模板和页数口径，不能套用中文摘要字数。

先完成正文、结果冻结和人工判断，再写最终摘要。摘要应在不看正文的情况下成立；不得写“见图 1”“由式 (5)”“详见附录”等外部指针。

## 2. 摘要的信息合同

摘要必须让评委快速回答：

| 问题 | 必需内容 |
|---|---|
| 研究什么 | 对象、核心目标和主要约束 |
| 难点是什么 | 非线性、耦合、冲突目标、数据缺失等真正困难 |
| 如何求解 | 每问的数学转化、模型/算法和关键工具 |
| 得到什么 | 每问至少一个可核验结论；有量化结果时优先给数值与基线 |
| 证据多强 | 验证、敏感性、误差、复杂度、可行性或证明边界 |
| 有何价值 | 只写建模者确认且证据支持的贡献与适用范围 |

`key_result_claim` 和 `contribution_claim` 是建模者判断。AI 不得从“模型跑通”自动推导“创新”，也不得替建模者选择哪组结果作为摘要头条。

## 3. 写作前证据矩阵

先在审计文件中建立矩阵，再写句子：

| Q | 任务/转化 | 方法 | 冻结结果 | 对照或稳健性 | 精确来源 | 可用主张 |
|---|---|---|---|---|---|---|
| Q1 | 需求预测 | LightGBM | RMSE 2.31 | ARIMA 3.08 | `frozen_numbers.json` 的键/行 | 测试误差低于该基线 |

执行规则：

- 数字、单位、样本范围、基线名称和舍入必须与冻结记录一致。
- 冻结文件只含 2.31 和 3.08 时，不直接写“降低 25.0%”；先把派生值加入规范结果源并重新冻结。
- “可行解”不能写成“最优解”；启发式算法找到的非支配解集不能自动写成真实 Pareto 前沿。
- 只做局部扰动时，只能声称“在所测范围内稳定”，不能声称普适。
- 模型含某个目标不等于该目标已改善。若没有碳排结果，不写“兼顾环境效益”。

## 4. 结构与题型适配

不强制固定段数，但推荐四个信息块：

1. **开篇**：核心问题、关键约束、总体策略；不要复述背景材料。
2. **逐问链条**：按题目顺序写“转化/切入点 → 方法 → 结果 → 必要的承接”。每问至少包含任务、方法、结果三项。
3. **验证与边界**：稳健性、灵敏度、误差、复杂度、证明范围或限制。
4. **价值与关键词**：采用建模者确认的贡献和主打结果，随后给 3-5 个关键词。

按任务调整重心：

| 任务类型 | 摘要重点 |
|---|---|
| 理论/证明 | 定义、关键引理或转化、可解性、复杂度、误差界 |
| 预测/拟合 | 数据尺度、模型、验证设计、误差指标、基线 |
| 优化/调度 | 目标与关键约束、求解器、可行性、目标值、对照方案 |
| 评价/决策 | 指标体系、权重或排序方法、稳定性、结论边界 |
| 仿真/机理 | 机制、参数、校准、情景范围、敏感性 |

不要按赛题字母机械判断题型；同一赛题的不同小问可以属于不同类型。

## 5. 语言和数字规则

优先使用可核验动作词：构建、定义、转化、分解、推导、证明、求解、比较、验证。删除“巧妙地、成功地、认真地、显然、众所周知、效果很好”等评价性修饰。

主张强度与证据匹配：

| 证据 | 可写 | 不可写 |
|---|---|---|
| 有明确基线 | “RMSE 低于 ARIMA 基线” | “全面优于现有方法” |
| 有最优性证书/证明 | “获得全局最优解” | 无证书时写“最优” |
| 只测有限扰动 | “在 ±5% 范围内稳定” | “具有普适性” |
| 单次样本外测试 | “在该测试集上达到...” | “证明模型可靠” |

缩写首次出现时给全称，公认且模板空间极紧时可保留常用缩写。通常不在摘要中放引文。公式只有在它本身就是核心贡献、无需正文定义也能理解时才使用。

关键词优先覆盖“研究对象 + 核心方法 + 任务/指标”，避免把五个具体算法都堆成关键词。

## 6. 完整示例

以下示例只演示证据组织，数字为示例工件中的已冻结值；不得挪作其他论文结果。

> 针对城市共享单车供需的时空失衡问题，本文建立需求预测、车辆调度与稳健性检验相衔接的建模框架。[MODELER INPUT NEEDED: which frozen result(s) should lead the abstract, and why?] 针对需求预测，清洗 18,240 条订单并以四分位距法识别异常记录，采用 LightGBM 预测站点小时需求；测试集 RMSE 和 MAE 分别为 2.31 和 1.64，ARIMA 基线的 RMSE 为 3.08。针对车辆调度，以缺车惩罚、调度成本和碳排放为目标建立多目标模型，采用 NSGA-II 生成候选非支配解，并使用建模者确认的折中方案；该方案将缺车率由 14.6% 降至 6.2%，日调度成本为 8,740 元。进一步在需求波动 ±10%、车辆故障率 0%-5% 的情景下检验模型，缺车率保持在 5.8%-7.1%，成本波动不超过 8.6%，说明方案在所测扰动范围内保持稳定。[MODELER INPUT NEEDED: what contribution should the paper claim, in the modeler's own words?]
>
> 关键词：共享单车；需求预测；多目标调度；稳健性分析

该稿仍是 `AWAITING_MODELER`，因为两个人工判断 sentinel 均未替换。最终提交稿不能保留 sentinel。

## 8. 常见错误

| 错误 | 修复 |
|---|---|
| 背景占据半页 | 压缩为一句问题定义，把篇幅给方法和结果 |
| 罗列模型名 | 补充每个模型解决哪一问及对应结果 |
| 每问只有方法没有数值 | 回到冻结结果；没有结果则不能宣称完成 |
| 自算提升率 | 进入规范结果源、复核并重新冻结 |
| “最优、显著、普适”无证据 | 改为可行、在测试范围内、相对指定基线 |
| 写“见图/表/式/附录” | 把必要结论直接写入摘要 |
| 所有句子以“针对问题 X”开头 | 保留题序，但用转化、方法或结论组织句子 |
| 关键词全是算法名 | 补研究对象和任务，删次要算法 |
| 经验字数当官方规则 | 回查当年通知与模板并记录来源 |
